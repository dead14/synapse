# Rencana Komprehensif: Overhaul Alignment Engine

## Konteks & Temuan Kunci

**Production path yang sebenarnya jalan:** `backend/dtw_engine.py` (GW matching via DTW) → `backend/hungarian_engine.py` (feature matching via Hungarian), berkomunikasi via JSON over stdin/stdout. Dipanggil oleh Express controller. (`engine/` package = orphaned dead code, dipakai sebagai referensi konsep saja.)

**Empat masalah teridentifikasi:**
1. **Data loncat**: anomali Metal Loss/Dent di-match GLOBAL lintas pipeline setelah GW ter-lock (`hungarian_engine.py:310-402`)
2. **GW matching lemah**: DTW hanya pakai weld, valve/tee TIDAK dipakai sebagai anchor; gap penalty & window kurang ketat
3. **Tidak ada confidence**: match hanya hard gate + cost, tanpa skor probabilistik (Naive Bayes hanya ephemeral di frontend `ProbabilityModal`)
4. **Recompute tiap load**: setiap buka halaman ILI Comparison → spawn python dari awal (lambat)

**Validasi riset literatur:** Paper [ADTH-DTW (MDPI 2026)](https://www.mdpi.com/2227-9717/14/9/1360) & [Dann & Maes 2017](https://www.sciencedirect.com/science/article/abs/pii/S0951832017300583) mengkonfirmasi hierarki **valve → weld → defect** adalah standar industri optimal. Asumsi user BENAR: valve sebaiknya dijadikan anchor pertama.

**Keuntungan tak terduga:** Frontend `IliComparisonPage.tsx` SUDAH siap untuk async job flow (`pollJobResult` line 45-94, cek `resData.jobId` line 108) — backend tinggal implement.

```
        │  └─ FASE E: NAIVE BAYES CONFIDENCE per pasangan
        │      Gaussian likelihood (dist/depth/length/width/clock) → %
        ▼
cache result ke Redis (key=session:{id}:results, TTL 1 jam)
        │
        ▼
return {comparison: [...], cached: false}
```

## Bagian 1 — Overhaul `backend/hungarian_engine.py` (inti)

### 1A. Strict Per-Joint Containment (eliminasi data loncat)

Port konsep dari `engine/matching.py:run_joint_centric_matching()`. Ganti bagian "2. Remaining features → Hungarian" (line 310-402):

1. **`build_joint_segments(gw_matches)`** — baru. Dari matched GWs (status='Match'), pasangan GW berurutan mendefinisikan joint:
   ```
   joint k = {old_lo, old_hi, new_lo, new_hi}  # batas dari GW[k] & GW[k+1]
   ```

2. **Pisahkan sisa fitur** jadi 2 kelompok:
   - **Anomali** (metal_loss, mechanical_damage, crack_like, lamination, weld_anomaly) → **PER-JOINT Hungarian**
   - **Landmark** (valve, tee, bend, offtake) → **GLOBAL Hungarian** (sparse, perlu match global)

3. **Per-joint Hungarian untuk anomali** — untuk setiap joint:
   - Kumpulkan anomali OLD dist ∈ `[old_lo, old_hi)`, anomali NEW dist ∈ `[new_lo, new_hi)`
   - Posisi anomali OLD dipetakan ke ruang NEW: `ratio = (old_dist-old_lo)/(old_hi-old_lo)` → `mapped = new_lo + ratio*(new_hi-new_lo)`
   - Cost = `|mapped_old - new_dist|` + soft penalty depth/clock (existing FIX #4)
   - Hungarian pada matriks kecil per-joint; threshold dalam-joint ketat (`dist_thresh_base`=0.3m)
   - Anomali tanpa pasangan di joint-nya → **unmatched** (strict, eliminasi 100% loncat)

4. **Edge case**: <2 matched GW → tidak ada joint → semua anomali unmatched + warning

### 1B. Naive Bayes Confidence

Port dari `ResultsPanel.tsx:54-74`. Fungsi baru `compute_confidence(f_old, f_new, dist_diff)`:

```python
L_dist   = exp(-dist_diff² / (2 * 0.5²))    # sigma=0.5m
L_depth  = exp(-d_depth² / (2 * 10²))       # sigma=10 %WT
L_length = exp(-d_length² / (2 * 20²))      # sigma=20mm
L_width  = exp(-d_width² / (2 * 20²))       # sigma=20mm
L_clock  = exp(-d_clock² / (2 * 1²))        # sigma=1hr
type_match = 1.0 if same family else 0.001
p_match = L_dist * L_depth * L_length * L_width * L_clock * type_match
confidence = clamp(p_match / (p_match + 0.05) * 100, 0, 100)
```
- Missing values → likelihood=1.0 (neutral, tidak menghukum)
- Hitung untuk setiap pasangan match (GW-locked + Hungarian) di `row_from_pair()`
- Field baru `"Confidence (%)"` di output row; unmatched → 0

## Bagian 2 — Overhaul `backend/dtw_engine.py` (valve-segmented)

### 2A. Valve Matching sebagai Anchor Pertama

Fungsi baru `match_valves(old_features, new_features)`:
- Filter Valve+Tee dari kedua run
- Hungarian match dengan toleransi ±200m (dari `engine/constants.py:LANDMARK_MATCH_TOL`)
- Cost = `|dist_old - dist_new|`
- Return valve pairs → **mega-segments** antara valve berurutan

### 2B. DTW GW Per Valve-Segment (bukan global)

Modifikasi `calculate_dtw()`:
- Setelah valve matching, **pecah pipeline jadi valve-segments**
- Jalankan DTW weld **per valve-segment** (weld di antara valve[k] dan valve[k+1])
- Gabungkan hasil DTW per-segmen
- Valve-segment dengan valve tunggal di salah satu sisi → fallback DTW global untuk segmen itu
- Jika tidak ada valve → fallback DTW global (backward compatible)

### 2C. Ketatkan DTW parameters
- Gap penalty lebih fisik: `gap_penalty = 2.0 + ota/4.0` (dari `ota/2.0`)
- Window fisik: `allowed_drift = max(old_dist, 50) * (ota/100)` (hapus `*2.0` yang terlalu longgar)
- Flag threshold tetap `0.05 + ota/100`

## Bagian 3 — Integrasi Redis Cache di `backend/src/modules/alignment/alignmentController.js`

### 3A. Redis Client + Graceful Fallback

Di `backend/src/config/redis.js` (file baru):
```js
const redis = require('redis');
let client = null;
try {
  client = redis.createClient({ url: process.env.REDIS_URL || 'redis://localhost:6379' });
  client.on('error', () => { client = null; });  // silent fail
  client.connect();
} catch { client = null; }
module.exports = { getClient: () => client };  // null jika Redis down
```

### 3B. Cache di `getIliResults`

```
GET /api/ili-results?sessionId=X
  cacheKey = `session:${X}:results`
  if redis:
    cached = redis.get(cacheKey)
    if cached: return {comparison: cached, cached: true}  // INSTANT
  spawn python hungarian_engine.py
  result = parse output
  if redis: redis.setEx(cacheKey, 3600, JSON.stringify(result.comparison))  // TTL 1 jam
  return {comparison: result.comparison, cached: false}
```

### 3C. Invalidation
- Saat `saveWizardState` / `saveSections` dipanggil (user ubah parameter) → `redis.del(cacheKey)`
- TTL otomatis 1 jam sebagai safety net

**Dependensi baru:** `redis` (npm) di `backend/package.json`. Redis opsional — jika down, sistem fallback ke spawn python (behavior saat ini), tidak crash.
